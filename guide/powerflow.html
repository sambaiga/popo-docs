Power flow#

popo.powerflow reads a solved circuit’s results as tables and steps a circuit through time. It needs the opendss extra.

Results of a solved circuit#

Each results function takes the opendssdirect module holding a solved circuit and returns a long DataFrame. Circuit has the same functions as methods, for example circuit.bus_voltages().

Function

One row per

bus_voltages()

bus and connected phase

line_currents()

line and phase

line_losses()

line

element_powers()

element and phase, for one element type

circuit_summary()

Time series#

solve_time_series() steps the circuit through its load shapes, by default in 30-minute steps. Here each customer is first given a household demand profile with assign_household_profiles() (see Scenarios).

import numpy as np

from popo.network import residential_loads
from popo.powerflow import solve_time_series
from popo.scenarios import assign_household_profiles

household_pool = pd.read_parquet("tests/data/uk_household_pu_96.parquet").to_numpy()
customers = residential_loads(dss)
assign_household_profiles(dss, customers, household_pool, np.random.default_rng(1))

transformers = list(circuit.transformers)
report = solve_time_series(dss, transformers, horizon=96, buses=[bus for _, bus in customers])

report.records has one row per step and monitored transformer: the active, reactive and apparent power at its secondary winding, the mean and minimum voltage on its secondary busbar, and the power at the head of the feeder. Passing buses also records the voltage at each of those buses, which voltage_traces() returns as one array per bus.

from popo.plotting import line_style, tokens

line_style.configure(latex=False)
traces = np.array(list(report.voltage_traces().values()))
hours = np.arange(96) / 2

busbar = report.records["v_lv_pu"].to_numpy()

fig, ax = line_style.new_panel()
ax.fill_between(hours, traces.min(axis=0), traces.max(axis=0), color=line_style.BAND_COLOR, lw=0,
                label="Customers")
ax.plot(hours, busbar, color=tokens.TEXT_MUTED, lw=line_style.LINE_WIDTH, label="Busbar")
ax.set_xticks([0, 12, 24, 36, 48])
ax.set_xlim(0, 48)
ax.set_xlabel("Hour")
line_style.set_y_axis(ax, traces, busbar)
ax.set_ylabel("Voltage (pu)")
line_style.finish(ax)
line_style.legend_below(ax, ncol=2)
line_style.show(fig)

Over the two days, customer voltages range from 1.015 to 1.041 pu, all below the busbar, which is held near 1.04 pu by the transformer.

Convergence#

A time-series solve can fail to converge at some steps, most often when many inverters run a Volt-VAr control loop. OpenDSS still reports a solution at those steps, so the report records how many steps diverged.

report.converged, report.diverged_steps, report.total_steps

(True, 0, 96)

At a diverged step, each recorded customer voltage is NaN. To stop a study when any step diverges, call require_convergence(), which raises ConvergenceError.

Penetration sweeps#

run_uk_sweep() and run_us_sweep() run a grid of EV and PV penetration levels on one feeder. Each scenario builds a fresh circuit from the same seed, so the customers who have PV at 40 % penetration still have it at 60 %. A sweep on this feeder takes several minutes, so it is not run on this page; the time series tutorial runs one.

Limitations#

  • The step length is fixed for a run, 30 minutes by default. Shorter events, such as a cloud passing, are averaged out.

  • A bus’s recorded voltage is the mean across its connected phases. For a single-phase customer that is the voltage it sees; for a three-phase bus it hides any imbalance between phases.

  • The solver iterates the inverter control loop up to 200 times per step by default. A step that needs more is reported as diverged; raise max_control_iterations only after checking why.
