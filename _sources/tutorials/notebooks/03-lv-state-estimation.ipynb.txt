    "# LV state estimation\n",
    "\n",
    "## Objectives\n",
    "\n",
    "<p style=\"text-align: justify\">Below the secondary substation, most low-voltage networks are not measured in real time: an operator knows the voltage and power at the busbar and little else, and cannot say what a given customer's voltage is right now without sending someone to measure it. State estimation infers the voltage at every bus from whatever is measured, plus a model of the network. This notebook asks how much has to be measured for that to work, on the same UK feeder as the time-series notebook:</p>\n",
    "\n",
    "<ul>\n",
    "<li style=\"text-align: justify\">Convert the OpenDSS feeder to pandapower with <code>popo.estimation.to_pandapower</code>, and check the conversion against OpenDSS with <code>check_conversion</code> before trusting it.</li>\n",
    "<li style=\"text-align: justify\">Count whether a measurement set can determine the state at all, with <code>observability</code>.</li>\n",
    "<li style=\"text-align: justify\">Estimate every bus voltage from the substation plus smart-meter readings with <code>estimate_voltages</code>, and score it against the true state with <code>voltage_error</code>.</li>\n",
    "<li style=\"text-align: justify\">Find out how many meters are enough, and whether line sensors can stand in for missing ones.</li>\n",
    "<li style=\"text-align: justify\">See how the quality of a substation forecast carries through to the estimate, with <code>run_comparison</code>.</li>\n",
    "</ul>\n",
    "\n",
    "<p style=\"text-align: justify\">State estimation needs pandapower: <code>uv add popo-flow[estimation]</code>.</p>"

    "\n",
    "<p style=\"text-align: justify\">OpenDSS has no state estimator; pandapower does. <code>to_pandapower</code> converts the feeder with pandapower's own OpenDSS converter, and <code>check_conversion</code> then solves both engines at the same loading and compares every bus.     "## 3. The substation alone\n",
    "\n",
    "<p style=\"text-align: justify\">An estimator solves for two unknowns at every bus, voltage magnitude and angle, less one reference angle: $2N - 1$ unknowns for $N$ buses. Every measurement supplies one equation, and so does each bus known to inject nothing, twice over (zero active and zero reactive power). <code>observability</code> counts the two before the estimator is run:</p>"
   ]
  },
  {
   "cell_type": "code",
   "execution_count": null,
   "id": "9",
   "metadata": {},
   "outputs": [],
   "source": [
    "noise = MeasurementNoise()\n",
    "\n",
    "\n",
    "def read(metered=(), sensors=(), seed=0):\n",
    "    \"\"\"Substation, meter and line-sensor readings with their instruments' noise, then an estimate.\"\"\"\n",
    "    r = np.random.default_rng(seed)\n",
    "    meter_p = active_mw * (1 + r.normal(0, noise.smart_meter_pq_fraction, customers))\n",
    "    meter_q = reactive_mvar * (1 + r.normal(0, noise.smart_meter_pq_fraction, customers))\n",
    "    flows = {\n",
    "        int(line): tuple(line_flows_true.loc[line].to_numpy() * (1 + r.normal(0, noise.line_pq_fraction, 2)))\n",
    "        for line in sensors\n",
    "    }\n",
    "    return estimate_voltages(\n",
    "        net,\n",
    "        lv_bus,\n",
    "        voltage_pu=v_true[lv_bus] + r.normal(0, noise.voltage_pu),\n",
    "        active_mw=substation_mw * (1 + r.normal(0, noise.substation_pq_fraction)),\n",
    "        reactive_mvar=substation_mvar * (1 + r.normal(0, noise.substation_pq_fraction)),\n",
    "        customer_active_mw=meter_p,\n",
    "        customer_reactive_mvar=meter_q,\n",
    "        metered=list(metered),\n",
    "        line_flows=flows,\n",
    "    )\n",
    "\n",
    "\n",
    "count = observability(net, lv_bus, metered=0)\n",
    "print(\n",
    "    f\"Unknowns: {count.required}. Equations from the substation alone: {count.available} (short by {count.shortfall}).\"\n",
    ")\n",
    "print(f\"Estimate from the substation alone: {'none' if read() is None else 'found'}\")"

    "## 6. Line sensors instead of meters\n",
    "\n",
    "<p style=\"text-align: justify\">An operator short of full smart-meter coverage can add power-flow sensors on a few lines instead. A sensor adds two equations, the same as a meter, so the count improves with every one. Whether the estimate does depends on where it goes: a sensor resolves an unmetered customer only if the flow it measures separates that customer from the others. The comparison below starts from 90% coverage (19 customers unmetered) and adds sensors either on randomly chosen lines or on the service line of each unmetered customer.</p>"
   ]
  },
  {
   "cell_type": "code",
   "execution_count": null,
   "id": "19",
   "metadata": {},
   "outputs": [],
   "source": [
    "def service_line(bus):\n",
    "    \"\"\"The line whose far end is a customer's bus.\"\"\"\n",
    "    return int(net.line.index[(net.line.to_bus == bus) | (net.line.from_bus == bus)][0])\n",
    "\n",
    "\n",
    "rows = []\n",
    "for s in range(TRIALS):\n",
    "    r = np.random.default_rng(1000 + s)\n",
    "    metered = r.choice(customers, round(0.9 * customers), replace=False)\n",
    "    unmetered = sorted(set(range(customers)) - set(metered))\n",
    "    placements = {f\"random, {k}\": r.choice(len(net.line), k, replace=False) for k in (25, 50, 100, 200)}\n",
    "    placements[f\"targeted, {len(unmetered)}\"] = [service_line(int(net.load.bus.iloc[i])) for i in unmetered]\n",
    "    placements[\"none\"] = []\n",
    "    for placement, sensors in placements.items():\n",
    "        estimate = read(metered, sensors, seed=s)\n",
    "        error = voltage_error(estimate, v_true)[\"max_abs_pu\"] if estimate is not None else np.nan\n",
    "        rows.append({\"placement\": placement, \"draw\": s, \"solved\": estimate is not None, \"max_error_pu\": error})\n",
    "\n",
    "sensors = pd.DataFrame(rows)\n",
    "sensor_summary = (\n",
    "    sensors.groupby(\"placement\", sort=False)\n",
    "    .agg(\n",
    "        solved=(\"solved\", \"sum\"),\n",
    "        median_max_error_pu=(\"max_error_pu\", \"median\"),\n",
    "        worst_max_error_pu=(\"max_error_pu\", \"max\"),\n",
    "    )\n",
    "    .reset_index()\n",
    ")\n",
    "sensor_summary[\"solved\"] = sensor_summary[\"solved\"].map(lambda n: f\"{n}/{TRIALS}\")\n",
    "themed_gt(sensor_summary, decimals=4)"
   ]
  },

Sensors on randomly chosen lines rarely help: most of the 377 lines are the service cables of customers who are already metered, so a sensor there adds equations without adding information. Fifty random sensors never solve; a hundred solve once in eight draws, and that one estimate is wrong by 0.35 pu, a reminder that a solved estimate is not a correct one and that its error has to be checked. Two hundred random sensors, more than half the lines, solve six times in eight.</p>\n",

    "## 7. When the substation reading is a forecast\n",
    "\n",
    "<p style=\"text-align: justify\">Everything above used the substation's measured state. An operator planning ahead has a forecast of it instead, and <code>run_comparison</code> asks whether the <em>kind</em> of forecast matters, at full meter coverage over a day of half-hours. Three substation inputs are fed to the same estimator: the true readings; a <em>coherent</em> forecast, one error applied to the demand and carried through a power flow, so its active power, reactive power and voltage describe a state the network can be in; and an <em>incoherent</em> one, each of the three perturbed on its own, as three separately calibrated forecasts would be. Both forecasts carry a 10% error.</p>"
   ]
